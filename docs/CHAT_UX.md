# Chat interface and image gestures

- The sidebar has a compact segmented choice for the next conversation: persistent history or temporary. Changing the choice does not convert the current room or change AI routing. The top bar labels the current room's retention state. Temporary expiration, hidden history, ownership and retained Inbox evidence keep their existing backend rules.
- Persistent room rows show a fallback title for empty names and a history label. They do not equate a room's legacy `privacy` value with the provider that actually runs; models still use workspace routing.
- File picker, clipboard paste and file drop share frontend validation: exactly one JPEG/PNG/WebP, nonempty, at most 8 MB. Backend decoding, pixel limit, sanitization, deduplication, tenant checks and confirmation requirements are unchanged. File transfer events never fetch clipboard URLs or HTML images.
- Selecting, pasting or dropping creates only a local object-URL preview. Upload occurs through the existing authenticated image endpoint only when the user submits. Object URLs are revoked on replacement/removal; changing room/workspace clears the pending image. Invalid input keeps a previously selected valid image and shows an inline error. Text-only paste retains native browser behavior; text accompanying an image is inserted at the textarea selection, with the existing 4,000-character limit.
- The app does not call the clipboard read API or request clipboard access to paste; it uses the user's paste event. Copy-answer uses a click-triggered clipboard write, with a readable failure message when unavailable (for example an insecure browser context). Visible Markdown is copied, without the hidden alternative confirmation code.
- Keyboard users retain desktop Enter to send, Shift+Enter for a new line, IME composition protection, and Escape to remove an unsent image. Mobile Enter stays a newline. The history drawer's focus trap includes search inputs. A jump-to-latest button lets users return after reading older messages.
- Starting a room clears the previous composer text immediately, before its asynchronous request. Text typed while creation finishes is retained.

No migrations, new environment variables, provider changes, broader upload types or automatic financial writes. Reference for paste/drop conventions: [Claude file and image upload guide](https://support.claude.com/en/articles/8241126-upload-files-to-claude).
