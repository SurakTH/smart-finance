# ลำดับส่งมอบ Smart Finance

แบ่งสถานะปัจจุบันเป็น 4 ขั้นเพื่อให้ติดตามง่าย ไม่ได้หมายความว่าฟีเจอร์ทั้งหมดตามแผนแรกเสร็จแล้ว

| ขั้น | งาน | สถานะ ณ 11 ตุลาคม 2026 |
|---|---|---|
| 1 — MVP แกนการเงิน | Docker, login, workspace isolation, double-entry, บัญชี/หมวดหมู่, รายการเงิน, dashboard, Inbox manual confirm, chat ข้อความ, provider management, Telegram linking/capture | เสร็จในขอบเขต MVP; integration จริงยังต้องตรวจขั้น 4 |
| 2 — รูปใน Web Chat | เลือกรูป/preview/นำออก, ส่งพร้อมข้อความ, ประวัติรูป, คิวอ่านภาพตาม privacy, สนทนา/ถามข้อมูลต่อ/ทวนและยืนยันรูปในแชท, กันรูปซ้ำ, tests | เสร็จและทดสอบกับ mock; provider vision จริงยังต้องตรวจขั้น 4 |
| 3 — ระบบใช้งานระยะยาว | จัดการสมาชิก/invites, reversal/correction พร้อม audit trail, budgets, เป้าหมายออม, รายการประจำ, export, Incognito/retention, chat streaming/search, PWA offline, ยืนยันอีเมล/กู้รหัสผ่าน, 2FA/อุปกรณ์ | เริ่มแล้ว: ค้นหา/กรองช่วงวัน/แบ่งหน้า, dashboard รายเดือน, chat รายงานจากข้อมูลจริง, บริการทั้งหมด, แยกบัญชี/หมวดหมู่, งบประมาณรายเดือน/แชทอ่านงบ และ correction/reversal พร้อม audit trail ส่งออก CSV รายการ/ประวัติ เป้าหมายออมพร้อมประวัติการจัดสรร รายการประจำที่รอยืนยันใน Inbox สมาชิก/คำเชิญพร้อมประวัติ และแชทชั่วคราว/อายุประวัติรายบุคคล และค้นหา/เปลี่ยนชื่อแชท ตั้งค่าบัญชีผู้ใช้ และแชททยอยตอบ พร้อมแผน AI จัดการบัญชี/หมวด/งบ/เป้าออม/รายการประจำสูงสุด10ขั้นตอน ยืนยันครั้งเดียว/atomic/ประวัติงานถาวร และคุยทั่วไปผ่าน Chat model/vision/Thinking ต่อโมเดล และบันทึก/แก้รายการด้วยภาษาธรรมชาติ/คำขอระบุช่องและพิมพ์แค่ “ยืนยัน” และยืนยันอีเมล/กู้รหัสผ่านผ่าน SMTP เสร็จ; ส่วนที่เหลือยังไม่เสร็จ |
| 4 — ยืนยันบนเครื่องปลายทาง | Ubuntu/Hyper-V, domain/HTTPS, backup schedule/restore drill, provider vision และ Ollama จริง, Telegram token จริง, load/security checks | Docker/backup restore ในเครื่องพัฒนาผ่านแล้ว; ยังไม่ได้ตรวจเครื่องปลายทางและบริการจริง |

**จุดปัจจุบัน: ขั้น 1–2 เสร็จในขอบเขต MVP → อยู่ระหว่างขั้น 3** correction/reversal พร้อมประวัติ ส่งออก CSV เป้าหมายออม รายการประจำ และสมาชิก/คำเชิญเสร็จแล้ว เพิ่มสมัครบัญชีผ่านเว็บโดยเปิด–ปิดด้วย ALLOW_REGISTRATION (ค่าเริ่มต้นปิด) พร้อม workspace ส่วนตัวแล้ว เพิ่มหน้าจัดการพื้นที่ เปลี่ยนชื่อ/เก็บเข้าคลัง/กู้คืน/ลบพื้นที่เริ่มต้นว่าง และรหัสชวนเพื่อนสร้างบัญชีส่วนตัวแยกกันแล้ว เพิ่มแชทชั่วคราว 24 ชม., retention 7/30/90 วัน และค้นหา/เปลี่ยนชื่อแชทแล้ว เพิ่มตั้งชื่อผู้ใช้และเปลี่ยนรหัสพร้อมเพิกถอนเซสชันแล้ว เพิ่มแชทแบบทยอยตอบพร้อมตรวจสิทธิ์และ fallback แล้ว เพิ่มบันทึก/แก้รายการผ่านแชท โดยทวนก่อน/หลังและรอข้อความยืนยันรหัสแล้ว รองรับภาษาธรรมชาติที่ตรวจด้วยกฎและถามข้อมูลเพิ่ม ยังไม่รองรับทุกสำนวนหรือการแก้ข้อมูลทุกประเภท เพิ่มเลื่อนโหลดข้อความเก่าต่อเนื่อง แชทภาษาธรรมชาติแบบกฎภาษาไทย ถามข้อมูลที่ขาด/แก้รายการที่ยืนยันล่าสุดในห้อง พร้อมใช้ทวนและยืนยันใน Telegram แล้ว เพิ่ม PWA install prompt และข้อมูล/ร่างออฟไลน์แบบเลือกเก็บและเข้ารหัสแล้ว เพิ่มยืนยันอีเมลและกู้รหัสผ่านผ่าน SMTP แบบเปิดเอง พร้อมคิวเข้ารหัส ลิงก์ใช้ครั้งเดียวและเพิกถอนเซสชันแล้ว งานถัดไปยังมี 2FA/จัดการอุปกรณ์ และการตรวจมือถือจริง/เครื่องปลายทางในขั้น 4; Incognito แบบไม่เขียนดิสก์ยังไม่ได้ทำ

ข้อจำกัดทุกฟีเจอร์และผลตรวจสอบอยู่ใน README และ VERIFICATION.md ตัวเลขบัญชีในภาพทดสอบเป็นข้อมูลสาธิต ไม่ใช่เงินของผู้ใช้ ไม่มีฟังก์ชันเคลื่อนย้ายเงินหรือเชื่อมบัญชีธนาคารจริง


อัปเดต AI: เพิ่ม native tools ค้นหารายการจริงและแก้ด้วยภาษาธรรมชาติ พร้อมถามเมื่อหลายรายการ ทวนก่อน/หลังและรอ “ยืนยัน”; วิเคราะห์รายเดือน/เดือนก่อน/งบจาก backend แล้วเสนอแผนปรับงบพร้อมเหตุผล ตรวจข้อมูลเปลี่ยนก่อนยืนยันแล้ว อยู่ระหว่างขั้น 3 เช่นเดิม ยังต้องตรวจคุณภาพโมเดลจริงและ Telegram native AI ในขั้นถัดไป


แชทใช้ลำดับโมเดล/fallback และ Cloud switch จาก workspace เดียวกันทุกห้องแล้ว ไม่เลือกโหมดรายห้อง ใช้ workspace ที่เลือกจากหน้าการเงินเป็นค่าเริ่มต้น จำเมื่อเปลี่ยนหน้า/รีโหลด และไม่ถามพื้นที่ซ้ำก่อนทำรายการ การแยก tenant และ typed confirmation คงเดิม


อัปเดตชุดรายการ AI: Web Chat เตรียมรายการใหม่สูงสุด10รายการจากข้อความ/รูป ทวนและยืนยันทั้งชุดแบบ atomic แก้ยอด/นำรายการในร่างออกตามหมายเลข ตรวจซ้ำใน workspace จาก ledger ก่อน/หลังทวนแล้ว ลด context และภาพซ้ำ พร้อม parser หลายรายการที่ระบุครบโดยไม่ใช้โมเดล ยังอยู่ขั้น3จาก4: ต้องตรวจโมเดลจริง/ใบเสร็จจริง/Ubuntu ปลายทาง และยังไม่มี multi-correction, Telegram native batch, การกระทบยอดใบแจ้งหนี้ provider หรือ memory summarization


อัปเดตเลขาส่วนตัว: ความจำแยกuser+workspace (บัญชีเริ่มต้น/กฎคำ→หมวด) แก้/ปิด/ล้างในSettingsและสั่งจำผ่านแชทพร้อมทวนยืนยัน; ถามเฉพาะข้อมูลที่ยังขาดและใช้ค่าเริ่มต้นที่เลือก; รายงานแนบการ์ดเปิดรายการต้นทาง; เจ้าของดูคำขอ/tokens/ค่าใช้จ่ายประมาณการแยกโมเดล ตั้งราคาและวงเงินรายเดือนจากเว็บได้แล้ว ครบ4ส่วนในขอบเขตนี้ ยังอยู่ขั้น3จาก4 ความจำไม่ใช่การเรียนรู้ข้อความอิสระอัตโนมัติ ค่าใช้จ่ายไม่ใช่ใบแจ้งหนี้หรือhard billing cap การใช้providerจริงและเครื่องUbuntuปลายทางยังต้องตรวจขั้น4
