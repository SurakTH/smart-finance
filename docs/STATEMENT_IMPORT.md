# นำเข้า statement / CSV

เปิด **บริการทั้งหมด → นำเข้า statement** (`/imports`) เลือกบัญชีเงินและไฟล์ CSV แล้วจับคู่ชื่อคอลัมน์ ระบบไม่เรียก AI และไม่ใช้ token

## ขั้นตอน

ก่อนนำเข้าบัญชีใหม่ ให้บันทึกยอดตั้งต้นก่อนช่วง statement หากมีเงินคงเหลือเดิม ระบบไม่สร้างยอดตั้งต้นจากยอดคงเหลือหรือยอดรวมใน CSV ให้อัตโนมัติ

1. ใช้ไฟล์ที่มีหัวคอลัมน์เป็นบรรทัดแรก รองรับ UTF-8 (มี/ไม่มี BOM), Thai Windows-874 และตัวคั่น comma, semicolon หรือ tab สูงสุด 2 MB / 500 รายการ / 50 คอลัมน์
2. เลือกวันที่แบบปี-เดือน-วัน หรือวัน/เดือน/ปี รองรับ ค.ศ./พ.ศ. 4 หลัก ระบบแนะนำรูปแบบจากแถวแรก และตรวจวันที่จริงทุกแถว
3. เลือกจำนวนเงินแบบแยกเงินเข้า/เงินออก หรือคอลัมน์เดียว (บวก = รายรับ ลบ = รายจ่าย) หากมีคอลัมน์ประเภทให้เลือกได้ จำนวนเงินเป็นบาท ทศนิยมไม่เกิน 2 หลัก ไม่ปัดทศนิยมส่วนเกิน
4. ตรวจรายการและเลือกหมวด หมวดที่ชื่อและประเภทตรงกับในไฟล์จะถูกจับคู่อัตโนมัติ กำหนดหมวดให้หลายแถวที่เลือกได้ โดยใช้เฉพาะประเภทรายรับ/รายจ่ายที่ตรงกัน
5. นำรายการโอนระหว่างบัญชี จ่ายบัตร ยอดรวม และยอดคงเหลือออกจากชุด แล้วกดทวนยอดและ **ยืนยันและบันทึกทั้งชุด**

ตัวอย่าง:

```csv
วันที่,รายละเอียด,เงินออก,เงินเข้า,หมวดหมู่
20/10/2569,กาแฟ,80,,อาหารและเครื่องดื่ม
20/10/2569,เงินเดือน,,30000,เงินเดือน
```

## การตรวจซ้ำและความถูกต้อง

- ตัวอย่างไม่ลง ledger และไม่สร้างบัญชีหรือหมวดใหม่เอง แถวข้อมูลผิดจะถูกปิดการเลือก แก้ไฟล์หรือการจับคู่คอลัมน์แล้วตรวจใหม่ได้
- ถ้ามีรหัสอ้างอิงธนาคาร ให้เลือกคอลัมน์นั้น ระบบใช้รหัสที่ hash แล้วแยกตาม workspace/บัญชีเพื่อจำรายการที่เคยนำเข้า รหัสซ้ำในไฟล์เดียวกันต้องตรวจแก้ก่อน
- ถ้าไม่มีรหัสอ้างอิง ใช้วันที่ ประเภท จำนวนเงิน รายละเอียด และลำดับของรายการที่เหมือนกันในไฟล์ การนำเข้าไฟล์เดิมจะข้ามรายการเดิม แต่ไฟล์ที่ครอบคลุมคนละช่วงและมีรายการเหมือนกันหลายรายการอาจแยกไม่ได้สมบูรณ์ ควรใช้รหัสธนาคารเมื่อมีและตรวจรายการที่ข้าม
- รายการที่ตรงกับ ledger เดิมจะขึ้น **อาจซ้ำ** ไม่เลือกอัตโนมัติ ต้องระบุว่าเป็นคนละรายการก่อนนำเข้า การตรวจนี้ไม่ได้ยืนยันว่าธุรกรรมเหมือนกันจริง
- การยืนยันตรวจซ้ำอีกครั้งภายใต้ workspace lock ใช้ double-entry posting เดิม และบันทึกทั้งชุดแบบ atomic ถ้าแถวหนึ่งผิด ทั้งชุดจะไม่ถูกบันทึก การส่งคำยืนยันเดิมซ้ำคืนผลเดิมโดยไม่เพิ่มยอด
- ผู้ใช้เปิด/ยืนยันได้เฉพาะชุดตัวอย่างของตนเองใน workspace ที่ยังมีสิทธิ์ ชุดตัวอย่างหมดอายุใน 24 ชั่วโมง worker ลบชุดที่หมดอายุและยังไม่ยืนยัน เก็บชุดที่ยืนยันแล้วเพื่อ audit/replay
- ไม่เก็บไฟล์ต้นฉบับ เก็บแถวที่แปลงแล้วบนเซิร์ฟเวอร์ ไม่ส่งข้อมูลให้ provider AI

## ขอบเขต

รองรับ CSV สำหรับรายรับ/รายจ่ายในบัญชีสินทรัพย์และ THB เท่านั้น ยังไม่รองรับ PDF, XLSX, การดึงข้อมูลธนาคารโดยตรง หรือ parser เฉพาะธนาคาร รายการโอน/จ่ายบัตรต้องใช้หน้าบันทึกรายการตามประเภทจริง การกระทบยอดยอดคงเหลือใน statement ยังไม่รวมในรุ่นนี้

การเปลี่ยนแปลงนี้มี migration `connections_and_imports` สำรองฐานข้อมูลและคีย์เดิมก่อนอัปเดต หากใช้ CI/CD ให้ deploy exact release ตาม [คู่มือ CI/CD](CICD.md)
