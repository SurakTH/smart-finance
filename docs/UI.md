# UX/UI รุ่นออกแบบใหม่

หน้าการเงินและ AI Chat ใช้โครงแอปคนละแบบ สร้างจากระบบเดิมที่ทำงานจริง โดยคง ledger และสิทธิ์ workspace; รุ่นรายงานเพิ่ม API สำหรับตัวกรองและยอดรวม

## หน้าการเงิน

- สีพื้นขาวนวล/เขียวอ่อน ตัวเลขยอดเงินเด่นกว่าป้ายอธิบาย ไม่มี gradient/การ์ดม่วงซ้อนกัน
- Desktop: navigation ด้านซ้ายขนาด 216px เนื้อหามีความกว้างสูงสุด 1320px รายจ่ายเดือนที่เลือกเป็นการ์ดหลัก พร้อมกราฟสะสม รายรับ/เงินเหลืออยู่ด้านข้าง หมวดใช้จ่ายเป็นวงกลมและกดดูรายการได้ ยอดบัญชีล่าสุดแยกจากช่วงเวลารายงานชัดเจน
- Mobile: header สั้นสำหรับชื่อแอป workspace และ settings; เมนูหลัก 5 ปุ่ม (ภาพรวม/รายการ/แชท AI/AI Inbox/ทั้งหมด) อยู่ด้านล่าง พร้อม safe-area สำหรับจอมี home indicator รายจ่ายและกราฟเต็มแถว รายรับ/เงินเหลือกับทางลัด AI อยู่คู่กัน
- Settings มีข้อมูลบัญชีและปุ่มออกจากระบบ ให้ใช้งานได้บนมือถือด้วย

## AI Chat

- เข้า /assistant แล้วใช้พื้นที่เต็ม viewport ไม่มี sidebar ของหน้าการเงิน หัวเรื่อง dashboard หรือเมนูด้านล่างมาแย่งพื้นที่
- Desktop เปิดประวัติด้านซ้ายโดยค่าเริ่มต้น สามารถซ่อนและเปิดใหม่ได้ Mobile ซ่อนประวัติโดยค่าเริ่มต้น เปิดเป็น drawer มี backdrop, focus trap, Escape และปุ่มปิด
- ส่วนหัวมีทางกลับหน้าการเงิน เปิดประวัติ และเริ่มห้องใหม่ โหมดของห้องและ workspace เลือกใน drawer
- เลื่อนเฉพาะข้อความ ช่องพิมพ์และแนบรูปอยู่ใน dock ด้านล่าง ยืดความสูงตามข้อความได้ถึง 144px ประวัติเลื่อนไปยังข้อความล่าสุดเมื่อมีคำตอบใหม่
- Desktop ใช้ Enter ส่ง / Shift+Enter ขึ้นบรรทัดใหม่ และไม่ส่งขณะ IME ยัง composing; Mobile ใช้ปุ่มส่งเพื่อคงการขึ้นบรรทัดใหม่จากแป้นพิมพ์
- หน้าต้อนรับมีปุ่มข้อความแนะนำ กดแล้วใส่ข้อความในช่องพิมพ์ให้ตรวจได้ก่อนส่ง
- รูปสลิป preview/นำออก/ดูย้อนหลังทำงานเหมือนเดิม รายละเอียดการแชร์หลักฐานใน workspace และข้อจำกัด mock อยู่ใน disclosure ใต้ช่องพิมพ์ โหมด Cloud มีข้อความแจ้งใกล้ช่องพิมพ์
- รองรับ dynamic viewport / VisualViewport resize / safe-area และ reduced motion; ยังไม่ได้ทดสอบแป้นพิมพ์จริงบน iOS/Android ทางกายภาพ

ดูผลทดสอบใน VERIFICATION.md และ browser tests ใน frontend/e2e สำหรับพฤติกรรมจริง

## รายงานและการเลือกวัน

Dashboard: ปุ่มเลื่อนเดือน + dialog ตาราง 12 เดือน พร้อมเลื่อนปี/กลับเดือนปัจจุบัน แสดงยอดเต็มเดือนเทียบเต็มเดือนก่อนอย่างชัดเจน ไม่อ้างว่าเป็นเทียบช่วงวันเท่ากัน ปุ่มในหมวด/บัญชีพาไป Transactions พร้อม query filters

Transactions: preset ช่วงเวลา + native date calendar ทั้งสองขอบเขต (inclusive), ค้นหาแบบ debounce, ประเภท/บัญชี/หมวด และ pagination 30 รายการ รวมยอดจากข้อมูลเต็มก่อนแบ่งหน้า รายการจัดกลุ่มวันและแสดงบัญชี/หมวดจริง สถานะ loading/ไม่พบรายการ/error และ reset ชัดเจน

AI Chat: รายงานช่วงวันคำนวณบนเซิร์ฟเวอร์ ไม่ใช้ LLM คำนวณหรือสร้าง SQL ระบุช่วงวันที่/ขอบเขตเสมอ; คำถามกว้างหรือช่วงเวลาที่ไม่รองรับขอระบุช่วงใหม่ รายงาน 20 รายการแรกพร้อมยอดเต็ม ส่วนคำแนะนำทั่วไปใช้ provider ตาม privacy เดิม

แนวทางอ้างอิง: [Actual Budget transaction filters](https://actualbudget.org/docs/transactions/filters/) และ [YNAB Spending Breakdown](https://www.ynab.com/whats-new/spending-breakdown-reflecting-on-web) นำหลักเลือกช่วง/กรอง/กดจากหมวดลงรายการมาปรับให้เข้ากับภาษาไทยและโครงข้อมูลของระบบ

## Services directory / แยกบัญชีและหมวดหมู่

- `/services` รวมบริการจริงเป็นกลุ่ม ดูแลการเงิน / ผู้ช่วยของคุณ / จัดการพื้นที่ของคุณ พร้อมค้นหาบริการและแสดงจำนวนบัญชี หมวดหมู่ และข้อเสนอรอยืนยัน ผู้ให้บริการ AI แสดงเฉพาะ owner
- Desktop มีเมนูหลักและลิงก์จัดการบัญชี/หมวดหมู่/ตั้งค่าแยกด้านล่าง ส่วนเมนูเลื่อนได้เมื่อหน้าจอเตี้ย Mobile คง 5 tab และใช้ “ทั้งหมด” เข้าถึงบริการรอง; tab นี้แสดงสถานะเลือกเมื่ออยู่หน้าจัดการด้วย
- `/accounts` แสดงยอดเงิน/หนี้และสร้างได้เฉพาะบัญชีเงินหรือหนี้สิน กดบัญชีไปดูรายการที่กรองแล้ว
- `/categories` แสดงหมวดรายจ่าย/รายรับคนละ tab เพิ่มหมวดได้เฉพาะสองประเภทนี้ กดหมวดไปดูรายการได้ การสร้างประเภทใน form ตาม tab ที่เลือก
- ปุ่มหัวหน้าบัญชี/หมวดหมู่พาไป form ที่ตรงหน้าพร้อม focus ชื่อ ไม่เปิดฟอร์มธุรกรรมแทน หน้า services มีทางลัดเพิ่มรายการเงิน
- Shortcut Telegram/privacy/provider ไปส่วนที่เกี่ยวข้องของ Settings หลังโหลดข้อมูลพร้อม ทั้งหมดใช้ API, tenant isolation และ ledger เดิม ไม่เพิ่มบริการจำลองหรือปุ่มที่ยังไม่ทำงาน

## งบประมาณรายเดือน

`/budgets`: ตัวเลือกเดือนแบบเดียวกับ Dashboard, สรุปวงเงิน/ใช้จริง/เหลือเฉพาะหมวดที่ตั้งงบ, การ์ดรายหมวดพร้อม progress และข้อความสถานะ, แสดงหมวดนอกงบแยกอย่างชัดเจน ไม่ใช้สีอย่างเดียวบอกสถานะ กดไปดูรายการที่กรองเดือน/หมวดได้

Modal ตั้งงบ/แก้ไขมี focus และชื่อที่เข้าถึงได้ นำวงเงินออกต้องตรวจชื่อหมวดและยืนยันใน dialog ป้องกันกดซ้ำระหว่างบันทึก ปุ่มคัดลอกเดือนก่อนเติมเฉพาะหมวดที่ขาด ไม่มีการเขียน ledger การเลือก workspace อยู่ต่อเมื่อเปลี่ยนหน้าและ reload ภายในแท็บ โดยตรวจ membership ก่อนคืนค่าที่เคยเลือก

เพิ่มบริการงบประมาณใน directory และ desktop sidebar มือถือคง 5 tab โดยเข้าจาก “ทั้งหมด” รองรับ loading/error/ไม่มีงบ/ไม่มีหมวด และสถานะเมื่อใช้จ่ายเกินงบ


## รายละเอียดรายการและประวัติ

กดแถวในหน้ารายการเงินเปิด dialog ที่ใช้ native focus trap/Escape แสดงวันที่ หมวด บัญชี และยอด ก่อนเข้าฟอร์มแก้ไขหรือยกเลิก ทุกการเปลี่ยนต้องระบุเหตุผลและยืนยัน ปุ่มป้องกันกดซ้ำระหว่างบันทึก ฟอร์มจำนวนเงินใช้บาทไม่เกินสองทศนิยม ไม่เปลี่ยนประเภทของรายการ ยอดตั้งต้นคงบัญชีเดิม

แยกประวัติออกจากยอดรวมปัจจุบันด้วยปุ่ม “ประวัติการแก้ไข” แสดงทุกเดือนใน workspace เป็นการ์ดก่อน/หลังพร้อมเหตุผลและเวลา แบ่งหน้า 30 เหตุการณ์ เปิดรายการเก่าหรือทดแทนต่อได้ รายการเก่าอ่านได้แต่แก้ซ้ำไม่ได้ Desktop แสดงก่อน/หลังสองคอลัมน์ Mobile เรียงลงหนึ่งคอลัมน์และเลื่อนภายใน dialog ได้


## ส่งออกข้อมูล

ปุ่ม “ส่งออก CSV” อยู่กับตัวกรองหน้ารายการ บอกชัดว่ารวมทุกแถวที่ตรงตัวกรองและจำนวนเงินเป็นบาท ระหว่างค้นหาหรือโหลดข้อมูลยังไม่พร้อม ปุ่มถูกปิดไว้ การเตรียมไฟล์แสดงสถานะและข้อผิดพลาดข้างปุ่ม เปลี่ยนตัวกรองหรือ workspace ระหว่างเตรียมไฟล์จะยกเลิกคำขอเก่า ไม่มีการดาวน์โหลดข้อมูลของพื้นที่เดิมตามหลัง

ประวัติการแก้ไขเพิ่มช่องวันตั้งแต่/ถึงตามวันที่เกิดการแก้ไข และปุ่ม “ส่งออกประวัติ CSV” ดาวน์โหลดทุกแถวที่ตรงช่วงนั้น จำนวนในหน้าแบ่งตาม 30 เหตุการณ์เช่นเดิม จอเล็กเรียงช่องวันในคอลัมน์เดียว มีทางเข้าจากบริการทั้งหมด → ส่งออกข้อมูล (owner 14 บริการ, member 13 บริการ)


## เป้าหมายออม

หน้า `/goals` ใช้ hero สีเขียวอ่อน แสดงยอดจัดสรรรวม/ยอดที่ยังขาด/จำนวนเป้าสำเร็จ และการ์ดเป้าหมายพร้อม progress วันที่ และสถานะ แยก tab กำลังใช้อยู่/เก็บไว้แล้ว มือถือเรียงคอลัมน์เดียว มีทางเข้าจาก “ทั้งหมด” โดยคง 5 tab หลักเดิม เดสก์ท็อปมีเมนูเป้าหมายออมเพิ่ม

ปุ่มตั้งเป้าหมาย/แก้ไข เปิด dialog ชื่อ/จำนวนบาท/วันครบกำหนด ปุ่มจัดสรรเพิ่ม/นำออก เปิดจำนวน/วันที่/บันทึกช่วยจำ ปุ่มประวัติแสดงรายการเพิ่ม/นำออกครั้งละ 30 เหตุการณ์ การเก็บ/เปิดใช้อีกครั้งต้องยืนยันก่อน ไม่ลบประวัติ ข้อความระบุชัดว่ายอดเป็นแผน ไม่เปลี่ยนหรือกันเงินจริงในบัญชี ฟอร์มผิด/ข้อมูล version เก่ามีข้อความแจ้ง ไม่แทนค่าที่คนอื่นแก้โดยเงียบ ๆ


## รายการประจำ

หน้า `/recurring` ใช้ hero โทนทรายและการ์ดรายรับ/รายจ่าย พร้อมยอดต่อรอบ บัญชี/หมวด วันที่ถัดไป และวันเริ่ม/สิ้นสุด แยก tab ใช้งาน/พัก/สิ้นสุดแล้ว มือถือเรียงหนึ่งคอลัมน์ มีทางเข้าจากทั้งหมดและเมนูเดสก์ท็อป คง mobile navigation 5 tab เดิม

ฟอร์มสร้างมีความถี่รายวัน/สัปดาห์/เดือนและวันเริ่ม-สิ้นสุด ฟอร์มแก้เปลี่ยนรายละเอียด/ยอด/บัญชี/หมวดเท่านั้น การพักและเปิดใหม่ต้องยืนยัน พร้อมอธิบายว่ารอบค้างจะทยอยสร้างเมื่อเปิดใหม่ ประวัติแสดงยอดตามแผนตอนสร้างข้อเสนอ สถานะ และทางไป Inbox/รายละเอียดรายการจริง ไม่อ้างว่าจำนวนตามแผนเท่ากับยอดที่ลงบัญชีแล้ว

Inbox มีป้ายรายการประจำและวันที่รอบ ฟอร์มยืนยันเติมข้อมูลต้นทางแต่ยังแก้ได้ ข้อเสนอจาก AI ยังใช้ flow เดิม หน้า Inbox polling ทุก 10 วินาทีเมื่อไม่มีงาน AI รอ เพื่อติดตามข้อเสนอจาก worker รายการเงินเปิดรายละเอียดตรง ID ผ่าน `entry_id` ใน URL ได้โดยตรวจสิทธิ์ workspace ฝั่ง API เช่นเดิม


## สมาชิกและคำเชิญ

`/members` ใช้การ์ดสมาชิกแทนตารางกว้าง มีชื่ออีเมล สิทธิ์ ป้าย “คุณ” และปุ่มเปลี่ยนสิทธิ์/นำออกเฉพาะเจ้าของพื้นที่ การออกจากพื้นที่ การเปลี่ยนสิทธิ์ และการยกเลิกคำเชิญต้องยืนยัน บนมือถือเรียงชื่อและปุ่มในแนวตั้ง ไม่บีบอีเมลให้ล้นจอ

เจ้าของเห็นฟอร์มเชิญด้วยอีเมล รหัสแสดงครั้งเดียวพร้อมคัดลอกรหัสและลิงก์ มีปุ่มซ่อนทันที ไม่เก็บใน browser storage หรือ URL แสดงคำเชิญรอรับก่อนประวัติเก่า และประวัติสมาชิกแบ่งหน้า 30 เหตุการณ์พร้อมผู้ดำเนินการ สมาชิกทั่วไปเห็นเฉพาะรายชื่อ สิทธิ์ ปุ่มออก และลิงก์รับคำเชิญ

`/join` เป็นหน้าแยกจาก dashboard ตรวจอีเมล/รหัสก่อนแสดงชื่อพื้นที่ ผู้รับใหม่ตั้งรหัสผ่านและยืนยัน ผู้มีบัญชีแล้วเข้าสู่ระบบเพื่อรับคำเชิญ หลังสำเร็จเลือกพื้นที่ที่เข้าร่วมและเปิดหน้าสมาชิก ลิงก์รับคำเชิญมีในหน้า login ด้วย บริการทั้งหมดเพิ่มสมาชิกและคำเชิญ ทำให้มี owner 14/member 13 บริการ มือถือคง 5 tab และเข้าถึงจาก “ทั้งหมด”


## อายุแชทและห้องชั่วคราว

เมนูในแชทเพิ่ม checkbox สำหรับห้องใหม่เป็นแชทชั่วคราว ไม่เปลี่ยนห้องเดิม เมื่อเปิดห้องชั่วคราวแสดงแถบโทนทรายบอกอายุ 24 ชม. พร้อมปุ่มจบและล้าง ไม่ใส่ห้องลงประวัติ โหมด Local/Cloud ยังแสดงแยกกัน หน้าตั้งค่าเพิ่มการ์ดอายุแชทส่วนบุคคลใน workspace เลือก 0/7/30/90 วันและต้องยืนยันผลต่อห้องเก่า มีข้อความว่าล้างแล้วไม่คืนข้อมูลและไม่รวม backup/Cloud


## ค้นหาประวัติและตั้งชื่อแชท

เมนูแชทเพิ่มช่องค้นหาชื่อ/ข้อความพร้อมล้างคำค้น ผลมีข้อความตัวอย่างและจำนวนห้อง แบ่งหน้า 20 ห้อง มี loading/error/retry/ไม่มีผลลัพธ์ Debounce 300 ms และยกเลิกคำค้นเก่าเมื่อเปลี่ยนคำหรือ workspace บนมือถือเปิดจากเมนูประวัติ กดผลแล้วปิดเมนูเพื่ออ่านข้อความ

เมื่อเปิดผลที่ตรงข้อความจะเลื่อนถึงข้อความและไฮไลต์ พร้อมแถบดูข้อความล่าสุด เมนูเปลี่ยนชื่อเปิดฟอร์มขนาดกะทัดรัดเหนือข้อความ บันทึกแล้วอัปเดตชื่อในประวัติ ห้องชั่วคราวไม่มีเมนูเปลี่ยนชื่อ และยังไม่อยู่ในผลค้นหา


บัญชีผู้ใช้เป็นการ์ดแรกในหน้าตั้งค่า: ชื่อที่แสดง/อีเมลอ่านอย่างเดียว และฟอร์มเปลี่ยนรหัสแยกกัน มี autocomplete ของตัวจัดการรหัสผ่าน สถานะกำลังบันทึก ผลสำเร็จและข้อผิดพลาด ไม่เปลี่ยน workspace เมื่อบันทึกชื่อ


แชท live preview แสดงคำว่า “กำลังตอบ · ยังไม่สมบูรณ์” และ cursor ที่หยุด animation ตาม prefers-reduced-motion การเชื่อมต่อสะดุดล้าง preview เพื่อไม่ให้เข้าใจว่าเป็นคำตอบสมบูรณ์ แล้วตรวจประวัติที่บันทึกแล้ว เมื่อเปลี่ยนห้อง/workspace/ออกจากหน้าแชท ปิด EventSource เดิมและล้าง preview; ไม่ได้ยกเลิก worker

## แชททวนก่อนบันทึก (11 ตุลาคม 2026)

มีคำแนะนำพับเก็บได้เหนือช่องพิมพ์ พร้อมปุ่มใส่ตัวอย่างคำขอ การบันทึกทวนรายละเอียด/ยอด/วันที่/บัญชี/หมวดหรือปลายทาง; การแก้แสดงก่อนและหลังพร้อมเหตุผล ผู้ใช้พิมพ์ “ยืนยัน” ภายใน 15 นาที (ผูกกับข้อความทวนล่าสุด) ไม่มีปุ่มที่ยืนยันแทนการพิมพ์ รายละเอียดรายการมีปุ่มคัดลอกคำขอแก้ไปวางในแชท รูปใน Web Chat คุยต่อ/ถามข้อมูลที่ขาด/ทวนก่อนยืนยันในแชทได้เมื่อเปิด Chat model ที่รองรับ vision โมเดลคุยทั่วไปได้และใช้ tool เสนอร่างที่ backend ตรวจอีกครั้ง การแก้รายการที่ลงแล้วรองรับเฉพาะคำขอแก้ที่ระบบกำหนด

## จัดการพื้นที่ทำงานและบัญชีแยกคน (11 ตุลาคม 2026)

หน้า `/workspaces` มีฟอร์มสร้างพื้นที่ ช่องค้นหา แท็บกำลังใช้งาน/ในคลัง แบ่งหน้าครั้งละ 6 พื้นที่ (ค้นหา/เปลี่ยนแท็บกลับหน้าแรก) และการ์ดบทบาท/จำนวนสมาชิก/จำนวนรายการบัญชีรวมประวัติ เจ้าของเปลี่ยนชื่อได้ เก็บ/กู้คืนต้องพิมพ์ชื่อ พื้นที่เริ่มต้นที่ยังว่างมีปุ่มลบถาวร ใช้ได้จาก sidebar หรือบริการทั้งหมดบนมือถือ ปุ่มทั้งหมดในแถบล่างยังมี 5 ปุ่ม

ส่วน “ให้เพื่อนมีบัญชีส่วนตัว” ออกโค้ดผูกอีเมลจากพื้นที่ที่เป็นเจ้าของ โดยไม่เพิ่มผู้รับเป็นสมาชิก หน้ารับคำเชิญแสดง “บัญชีแยก” และปุ่มสร้างบัญชีส่วนตัว ส่วนโค้ดแชร์พื้นที่ยังแสดงสิทธิ์สมาชิก หน้า Members ระบุประเภทโค้ดชัดเจน Settings ลิงก์มาหน้าจัดการพื้นที่แทนฟอร์มสร้างเดิม หากไม่มีพื้นที่ที่ใช้งานอยู่ ยังเข้าแก้บัญชีผู้ใช้/จัดการพื้นที่/กู้คืนได้

## แชทธรรมชาติและการอ่านย้อนหลัง

ใช้ข้อความธรรมชาติหนึ่งรายการ เช่น “กาแฟ 75 จากเงินสด” ระบบถามชื่อบัญชี/หมวดที่ขาดต่อในห้องเดิมได้ ภายใน 15 นาที ทุกข้อเสนอมีรายละเอียดทวนและรหัสยืนยัน แก้รายการที่ยืนยันล่าสุดในห้องได้โดยแสดงก่อน–หลัง รองรับคำขอที่ตัวแปลแบบกฎอ่านได้ ไม่อ้างว่ารองรับทุกสำนวน Telegram ข้อความใช้ handler เดียวกัน ส่วนภาพสลิปยังตรวจที่ Inbox บนเว็บ

โหลด 50 ข้อความล่าสุด เลื่อนขึ้นหรือกดปุ่มเพื่อเติมข้อความเก่า รักษาตำแหน่งเมื่อเติมด้านบนและไม่ทิ้งข้อความเก่าระหว่าง polling โหลดใหม่เฉพาะห้อง/ผลค้นหาที่เลือก มีลิงก์จากร่างออฟไลน์เข้าห้องสนทนาโดยตรง

## ติดตั้งและออฟไลน์

ตั้งค่ามีปุ่มติดตั้งเมื่อ browser ส่ง install prompt และคำแนะนำเพิ่มหน้าจอหลัก หน้าเก็บข้อมูลออฟไลน์ให้ตั้งรหัสแยกและเลือก workspace ก่อนเก็บ snapshot 100 รายการล่าสุด เข้ารหัสบนเครื่องโดยปิดเป็นค่าเริ่มต้น

หน้าออฟไลน์ใช้พื้นขาวนวล/เขียวและตัวอักษรระบบเพื่อเปิดได้แม้ไฟล์ฟอนต์แอปยังไม่เคยโหลด ปลดล็อกแล้วดูเวลาของ snapshot ยอดบัญชี รายการ และร่างข้อความได้ เมื่อกลับออนไลน์ต้องกดส่งร่างให้ทวน แล้วพิมพ์ยืนยันอีกครั้ง ข้อความจาก vault/server ใส่ผ่าน textContent ไม่ตีความ HTML มีล็อกเมื่อไปเบื้องหลังและล้างข้อมูลบนเครื่องพร้อมร่างเมื่อ logout ไม่แสดงว่า snapshot เป็นยอดสด


ยืนยันอีเมล/กู้รหัสผ่าน: ลิงก์ “ลืมรหัสผ่าน?” อยู่หน้าเข้าสู่ระบบ พร้อมแจ้งเมื่อ SMTP ปิด ตั้งค่าบัญชีมีสถานะอีเมลและปุ่มขอลิงก์ เปิดลิงก์แล้วยังต้องกดยืนยันหรือกรอกรหัสผ่านสองครั้งเอง ลบ fragment จากที่อยู่ทันที ไม่แสดง token บนหน้าจอ รีเซ็ตรหัสผ่านสำเร็จให้กลับเข้าสู่ระบบใหม่ทุกอุปกรณ์ ไม่เข้าระบบให้อัตโนมัติ


## งานจัดการผ่านผู้ช่วย

แชททวนแผนบัญชี/หมวด/งบ/เป้าออม/รายการประจำได้สูงสุด10ขั้นตอน แสดงก่อน–หลังและผลกระทบก่อนให้พิมพ์ยืนยันครั้งเดียว ไม่ลงเงินจากแผนจัดการ เมนูแชทมี “ประวัติงานผู้ช่วย” เปิด dialog ดูผู้ยืนยัน เวลา และแผนที่สำเร็จ แบ่งหน้าครั้งละ10 ข้อความแสดงเป็น text ไม่ตีความ HTML ประวัตินี้แชร์ตาม workspace และไม่หายเมื่อลบแชท


AI Web Chat: ตัวอย่างคำสั่งในหน้าความสามารถเพิ่มค้นหา/แก้รายการและวิเคราะห์เพื่อปรับงบ ใช้ข้อความทวนก่อน/หลังและประวัติการแก้เดิม การเสนอปรับงบแสดงตัวเลขจริงจากระบบแยกกับเหตุผลที่โมเดลเสนอ ถ้าค้นพบหลายรายการแสดงรายการมีหมายเลขให้พิมพ์เลือกก่อน ไม่เพิ่มหน้าฟอร์มหรือบังคับคัดลอกคำสั่งรูปแบบตายตัว


Web Chat ไม่มีตัวเลือก Private/Online รายห้อง ใช้การตั้งค่าและลำดับโมเดลของ workspace ทุกครั้ง หัวแชทแสดงชื่อพื้นที่ที่เลือกและป้าย AI ตามลำดับ ชื่อยาวตัดด้วย ellipsis เพื่อไม่ล้นมือถือ ตัวเลือก workspace ใช้ค่าเดียวกับหน้าการเงินและจำทันทีใน sessionStorage ของแท็บนั้น ผู้ช่วยใช้พื้นที่นี้โดยไม่ถามซ้ำก่อนทำรายการ เปลี่ยนเองได้จาก selector เดิม


แชทแสดงชุดรายการใหม่เป็นหมายเลข (สูงสุด10) พร้อมยอด/วัน/บัญชี/หมวดแต่ละรายการและคำเตือนอาจซ้ำ ร่างแก้ได้ด้วย `แก้ยอดรายการที่ 2 เป็น 90 บาท` / `ลบรายการที่ 2` และทวนชุดใหม่ก่อน `ยืนยัน` ครั้งเดียว ไม่มีปุ่มโพสต์จากผลโมเดลโดยตรง คำแนะนำหน้าแชทเพิ่มตัวอย่างหลายรายการแล้ว


แก้ streaming scroll: เคารพสถานะติดตามท้ายแชทเมื่อผู้ใช้เลื่อนขึ้น หยุดการดึงกลับจาก threshold360px เดิม รองรับ wheel/touch/scroll และไม่บีบความสูงของ message/thinking child เพิ่ม dedupe งาน SSE ที่คำตอบจริงโหลดแล้ว ป้องกัน late snapshot แสดงซ้อนและไม่แสดงร่างของห้องเดิมชั่วคราวระหว่างเปลี่ยนห้อง ยืนยันขณะงานในห้องเดียวกันยังคิดอยู่ให้รอทวน ไม่มีการยืนยันล่วงหน้า
